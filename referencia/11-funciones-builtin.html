any() y all()

notas = [88, 72, 95]
any(n >= 50 for n in notas)    # True  — ¿alguno?
all(n >= 50 for n in notas)    # True  — ¿todos?

# Se paran en cuanto lo saben (short-circuit):
any([False, True, False])      # lee 2 elementos y para
all([True, False, True])       # lee 2 elementos y para
El caso vacío: any([]) → False; all([]) → True (verdad vacua: no hay ninguno que incumpla). Si la colección vacía significa un problema en tu código, comprueba aparte: if datos and all(...).

min() / max()

max(["sol", "ventana", "mar"], key=len)     # 'ventana'

candidatos = {"Ana": 88, "Lucía": 95}
max(candidatos, key=candidatos.get)          # 'Lucía' (la clave, no el valor)

min([], default="sin datos")                 # 'sin datos'
min([])                                      # ValueError

En caso de empate gana el primero que aparece.

sum()

sum([1, 2, 3])                  # 6
sum([1, 2, 3], 10)              # 16   — segundo argumento = valor inicial
sum(n >= 80 for n in notas)     # 2    — cuenta: True vale 1, False vale 0
No uses sum() para concatenar listas: es O(n²). Usa itertools.chain().

zip() — el bug silencioso

list(zip(["a","b","c"], [1,2]))                # [('a',1), ('b',2)] ← pierde 'c'
list(zip(["a","b","c"], [1,2], strict=True))   # ValueError

# strict= existe desde Python 3.10 (PEP 618)

Numéricas y de secuencia

abs(-7)                  # 7
pow(2, 10)               # 1024      — igual que 2 ** 10
pow(2, 10, 1000)         # 24        — (2**10) % 1000 en un paso
divmod(17, 5)            # (3, 2)    — cociente y resto
round(2.675, 2)          # ojo: redondeo bancario, ver ficha 01

list(enumerate(["a","b"], start=1))   # [(1,'a'), (2,'b')]
list(reversed([1, 2, 3]))             # [3, 2, 1]  — iterador perezoso
[1, 2, 3][::-1]                       # [3, 2, 1]  — copia en memoria
sorted(datos, key=..., reverse=True)  # lista nueva; estable en empates
