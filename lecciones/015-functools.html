El módulo functools

Pista 4, lección 5 — herramientas que operan sobre funciones

functools es la caja de herramientas funcional de la librería estándar. Todo lo que hay dentro tiene la misma forma: recibe una función y devuelve algo. Son funciones de orden superior de la lección 012, ya escritas y probadas por ti.

reduce — plegar una colección en un valor

Es la tercera pieza del trío clásico. map transforma N en N, filter reduce N a M, y reduce colapsa N en uno. 

from functools import reduce

reduce(funcion_de_dos_argumentos, iterable, valor_inicial)

La función recibe dos cosas: el acumulado hasta ahora y el siguiente elemento. Devuelve el nuevo acumulado.

reduce(lambda acc, x: acc + x, [1, 2, 3, 4], 0)
acc=0, x=1 → 1 acc=1, x=2 → 3 acc=3, x=3 → 6 acc=6, x=4 → 10

Ese ejemplo concreto no lo escribas nunca: sum([1,2,3,4]) hace lo mismo y se lee mejor. reduce gana cuando la operación no tiene una builtin propia: 

# Producto (no hay builtin... salvo math.prod, que también existe)
reduce(lambda a, b: a * b, [1, 2, 3, 4, 5], 1)     # 120

# Intersección de varios conjuntos
reduce(lambda a, b: a & b, [{1,2,3}, {2,3,4}, {3,4,5}])   # {3}

# Fusionar diccionarios sin mutar ninguno
reduce(lambda a, b: {**a, **b}, [{"a":1}, {"b":2}, {"c":3}])

# Aplicar una lista de funciones en cadena — ¡el componer() de la lección 012!
reduce(lambda valor, f: f(valor), [limpiar, minusculas, sin_tildes], texto)
Ese último ejemplo merece un segundo de atención: el acumulador no tiene por qué ser un número. Aquí el acumulado es el texto en curso y los "elementos" son funciones. Toda composición es un reduce.
Sobre el valor inicial. Si lo omites, reduce usa el primer elemento como semilla — y revienta con TypeError si el iterable está vacío. Ponlo siempre que exista un neutro obvio (0 para sumar, 1 para multiplicar, {} para fusionar).

Guido tenía razón a medias. Van Rossum sacó reduce de las builtins en Python 3 porque «casi siempre un bucle explícito es más legible». En la práctica: usa sum, min, max, math.prod, any, all o str.join cuando existan. Reserva reduce para lo que no cubren.

partial — fijar argumentos

partial coge una función y unos cuantos argumentos, y devuelve una función nueva con esos argumentos ya puestos. Es la fábrica de closures de la lección 012, sin escribir el def interno. 

from functools import partial

def baremar(experiencia, formacion, peso_exp, peso_form):
    return experiencia * peso_exp + formacion * peso_form

# El baremo de esta convocatoria: 70 % experiencia, 30 % formación
baremo_2026 = partial(baremar, peso_exp=0.7, peso_form=0.3)

baremo_2026(experiencia=8, formacion=6)    # 7.4

Compara con el closure equivalente:

# A mano
def hacer_baremo(peso_exp, peso_form):
    def baremo(experiencia, formacion):
        return baremar(experiencia, formacion, peso_exp, peso_form)
    return baremo

# Con partial — cuatro líneas menos, misma cosa
baremo_2026 = partial(baremar, peso_exp=0.7, peso_form=0.3)

Dónde brilla de verdad

# Adaptar una función a la firma que espera otra API
sorted(candidatos, key=partial(distancia_a, origen="Sevilla"))

# Especializar por configuración
int_binario = partial(int, base=2)
int_binario("1011")            # 11

# Callbacks con contexto ya inyectado
boton.on_click(partial(guardar, destino="/tmp/salida.csv"))
Posicionales vs. nombrados. partial fija los posicionales por la izquierda: partial(f, 1) hace que el 1 sea el primer argumento, y no puedes saltarte el segundo. Si necesitas fijar el de en medio, usa el nombre: partial(f, tercero=3).

lru_cache — memorizar resultados

Aquí se cobra la factura de la lección 011. Si una función es pura, su resultado depende sólo de los argumentos — así que se puede guardar y reutilizar. @lru_cache hace eso automáticamente. 

from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

Sin caché, fib(35) hace unos 30 millones de llamadas y tarda segundos: el árbol de recursión recalcula fib(10) miles de veces. Con caché, cada n se calcula una sola vez y el coste pasa de O(2n) a O(n). Es programación dinámica (Pista 1) en una línea. 

fib(100)              # instantáneo
print(fib.cache_info())
# CacheInfo(hits=98, misses=101, maxsize=None, currsize=101)

fib.cache_clear()     # vaciar la caché

Requisitos para poder cachear:

1. La función debe ser pura. Cachear obtener_saldo(cuenta) te devolverá saldos obsoletos para siempre.

2. Los argumentos deben ser hashables (lección 011). Una lista como argumento da TypeError: unhashable type. Pásale una tuple o un frozenset.

LRU = Least Recently Used. Con maxsize=128 (el defecto), al llenarse tira lo menos usado recientemente. Con maxsize=None la caché crece sin límite — cómodo para recursión acotada, peligroso para funciones con dominio grande, porque nada se libera nunca. Desde Python 3.9 tienes @cache, que es exactamente @lru_cache(maxsize=None) con un nombre más honesto.

wraps — no perder la identidad

Esta es pequeña pero imprescindible, y es la puerta a la lección 017. Cuando envuelves una función en otra, la original desaparece de la vista: 

def cronometrar(funcion):
    def envoltorio(*args, **kwargs):
        ...
        return funcion(*args, **kwargs)
    return envoltorio

@cronometrar
def calcular_baremo(candidato):
    """Aplica el baremo oficial de la convocatoria."""
    ...

print(calcular_baremo.__name__)   # 'envoltorio'  😱
print(calcular_baremo.__doc__)    # None          😱
help(calcular_baremo)             # inútil

El nombre, el docstring, las anotaciones de tipo — todo se ha perdido. Los tracebacks mentirán, help() no servirá, y las herramientas que introspeccionan (pytest, Sphinx, FastAPI) se confundirán. Una línea lo arregla: 

from functools import wraps

def cronometrar(funcion):
    @wraps(funcion)                    # ← copia __name__, __doc__, __module__…
    def envoltorio(*args, **kwargs):
        ...
        return funcion(*args, **kwargs)
    return envoltorio

print(calcular_baremo.__name__)   # 'calcular_baremo' ✅
print(calcular_baremo.__doc__)    # 'Aplica el baremo oficial…' ✅
Regla sin excepciones: todo decorador que escribas lleva @wraps. Si se te olvida, no falla nada hoy — falla dentro de tres meses, cuando un traceback te mienta sobre qué función reventó.

Menciones rápidas

from functools import cache, cached_property, singledispatch, cmp_to_key

@cache                      # = lru_cache(maxsize=None), Python 3.9+
def costoso(n): ...

class Informe:
    @cached_property        # se calcula la 1ª vez y se guarda en la instancia
    def estadisticas(self): ...

@singledispatch             # sobrecarga por tipo del primer argumento
def formatear(valor): return str(valor)

@formatear.register
def _(valor: list): return ", ".join(map(str, valor))

# cmp_to_key: adaptar una función de comparación antigua (-1/0/1) a key=
sorted(items, key=cmp_to_key(mi_comparador))
singledispatch es lo más parecido al polimorfismo de OOP que hay aquí: en vez de que cada clase lleve su método, la función se ramifica según el tipo. Es despacho sin herencia.
