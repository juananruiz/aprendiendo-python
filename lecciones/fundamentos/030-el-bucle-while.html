El bucle while, de arriba abajo

Todos los patrones, de un vistazo — y por qué ya has usado casi todos sin darte cuenta

Ya usas while desde tus primeros scripts. Esta lección no te enseña la sintaxis básica (eso ya lo tienes marcado como hecho en el TEMARIO) — te enseña el espectro completo: los patrones con los que aparece en código real, incluido el tuyo, y los dos huecos que seguían sin marcar: while/else y el trío break/continue/pass.

Lo único que while hace de verdad

Antes de cada vuelta (incluida la primera), Python evalúa la condición. Si es verdadera, ejecuta el cuerpo y vuelve a evaluar. Si es falsa, sale. Eso es todo lo que hace un while. Todo lo demás en esta lección son formas de rellenar esa condición. 
while condicion:
    # cuerpo — se repite mientras condicion sea True
A diferencia de otros lenguajes, Python no tiene do...while (ejecutar el cuerpo al menos una vez, y comprobar la condición al final). Si lo necesitas, lo simulas con while True y un break al final del cuerpo — lo ves en la sección 3.

1. Patrón contador

El que ya conoces: una variable que avanza en cada vuelta hasta cumplir una condición numérica.

i = 0
while i < 5:
    print(i)
    i += 1     # si olvidas esta línea, bucle infinito — ver sección 7

2. Patrón centinela

Procesas datos hasta encontrar un valor especial ("centinela") que marca el final — típico al leer datos de usuario o de un stream, sin saber de antemano cuántos van a llegar. 

total = 0
i = 0
while i < len(numeros) and numeros[i] != -1:   # -1 es el centinela
    total += numeros[i]
    i += 1
El orden de la condición importa: i < len(numeros) and numeros[i] != -1 funciona porque Python evalúa and de izquierda a derecha y para en cuanto algo es falso (short-circuit). Si lo escribieras al revés, numeros[i] != -1 and i < len(numeros), podrías acceder a numeros[i] con un i ya fuera de rango.

3. Patrón bandera (flag)

Una variable booleana que resume "¿debo seguir?". Ya lo usaste tú mismo, sin ponerle nombre, en algoritmos/orden_burbuja.py: 

cambio = True
while cambio:
    cambio = False
    for i in range(n - 1):
        if lista[i] > lista[i + 1]:
            lista[i], lista[i + 1] = lista[i + 1], lista[i]
            cambio = True   # si hubo un intercambio, hace falta otra vuelta

La bandera cambio responde a una pregunta que un simple contador no puede responder: "¿ha pasado algo interesante en esta vuelta?". Mientras la respuesta sea sí, sigues.

3.5. while True + break: el bucle sin condición de entrada

A veces no sabes de antemano cuántas vueltas harán falta, y la condición de parada solo se puede comprobar dentro del cuerpo. Ahí usas while True (siempre verdadero) y sales con break — o, como aquí, con return. Ya lo hiciste en algoritmos/babylonian_square_root.py: 

def babylonian_squareroot(n):
    guess = n / 2.0
    while True:
        better_guess = (guess + n / guess) / 2.0
        if math.isclose(guess, better_guess):
            return better_guess   # la condición de parada vive AQUÍ dentro
        guess = better_guess
Esto es el do...while que Python no tiene: el cuerpo se ejecuta siempre al menos una vez, y la decisión de parar se toma al final de cada vuelta, con toda la información fresca de esa vuelta.

4. break, continue y pass

PalabraQué hace
breakSale del bucle inmediatamente, sin terminar la vuelta actual ni volver a comprobar la condición
continueSalta el resto del cuerpo de esta vuelta y va directo a comprobar la condición de la siguiente
passNo hace nada. Es un "cuerpo vacío" — un marcador de sitio para código que aún no has escrito
i = 0
while i < 10:
    i += 1
    if i == 3:
        continue      # salta el print de este 3, pero sigue el bucle
    if i == 7:
        break         # sale del todo al llegar a 7
    print(i)
# Imprime: 1 2 4 5 6
pass no tiene nada que ver con controlar el flujo de un bucle — es simplemente la forma de decir "aquí no hay nada, pero sintácticamente necesito algo". Verás mucho pass en los esqueletos de ejercicio de este sitio, marcando dónde falta tu código.

5. while / else

El bloque else de un while se ejecuta solo si el bucle terminó porque la condición se volvió falsa — nunca si terminó por un break.

Ya lo usaste en algoritmos/busqueda_binaria_02.py:

while min <= max:
    posicion = (min + max) // 2
    if numero == lista[posicion]:
        print("Número encontrado")
        break
    elif numero > lista[posicion]:
        min = posicion + 1
    else:
        max = posicion - 1
else:
    print("No se ha encontrado el elemento en la lista")

Si encuentras el número, hay un break → el else no se ejecuta. Si el bucle agota todas las posiciones sin encontrarlo, la condición min <= max se vuelve falsa por sí sola → el else sí se ejecuta.

Mentalmente, lee while ... else como "si no hubo break". Es la traducción literal y evita la confusión con el else de un if.

6. Bucles anidados

fila = 0
while fila < 3:
    columna = 0
    while columna < 3:
        print(f"({fila},{columna})", end=" ")
        columna += 1
    print()
    fila += 1
Ojo con break en bucles anidados: solo sale del while más interno, no de los dos. Si necesitas salir de ambos de golpe, lo habitual es usar una bandera comprobada también en el bucle exterior, o extraer el bucle interno a una función y hacer return.

7. El bug clásico: el bucle infinito de verdad

Todos los patrones de arriba comparten un riesgo: si nada dentro del cuerpo cambia el resultado de la condición, el bucle no termina nunca. 

# ❌ Bucle infinito: falta actualizar i
i = 0
while i < 5:
    print(i)
    # i += 1   ← si esta línea no está, i siempre vale 0, la condición
    #            siempre es True, y esto no termina jamás
Checklist mental antes de ejecutar cualquier while que hayas escrito tú: ¿hay, dentro del cuerpo, al menos una línea que cambia alguna variable que aparece en la condición? Si la respuesta es no, tienes un bucle infinito garantizado.

while vs for: cuándo usar cada uno

Usa for cuando...Usa while cuando...
Sabes de antemano sobre qué vas a iterar (una lista, un range())No sabes cuántas vueltas harán falta — depende de una condición que se decide en marcha
Recorres una colección enteraEsperas una condición externa: convergencia, entrada de usuario, un centinela

Regla rápida: si en algún momento piensas "voy a llevar la cuenta yo mismo de en qué posición estoy", probablemente deberías estar usando for con enumerate() (lección 0001) en vez de un while con un contador manual.
