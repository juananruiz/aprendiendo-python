Funciones a fondo

Parámetros, argumentos y el scope — todo lo que va entre los paréntesis

Escribes funciones desde tu primer script. Esta lección va de la mitad que no se suele enseñar: cómo se pasan de verdad los argumentos, por qué a veces una variable «no se deja modificar», y el error más famoso de Python — que no es un error del lenguaje, sino de expectativas.

1. Argumentos posicionales y por nombre

def crear_usuario(nombre, edad, ciudad):
    return {"nombre": nombre, "edad": edad, "ciudad": ciudad}

crear_usuario("Ana", 28, "Sevilla")                    # posicionales: el orden manda
crear_usuario(ciudad="Sevilla", nombre="Ana", edad=28) # por nombre: el orden da igual
crear_usuario("Ana", ciudad="Sevilla", edad=28)        # mezcla: posicionales primero
Cuándo usar cada uno. Si al leer la llamada no se entiende qué significa un argumento, ponle nombre. dividir(7, 2, True) no dice nada; dividir(7, 2, redondear=True) se lee solo. Es el mismo criterio que aplicas al nombrar variables.

2. Valores por defecto

def saludar(nombre, saludo="Hola"):
    return f"{saludo}, {nombre}"

saludar("Ana")                  # 'Hola, Ana'
saludar("Ana", "Buenos días")   # 'Buenos días, Ana'

Los parámetros con valor por defecto van siempre al final: si no, Python no sabría qué argumento corresponde a cuál.

3. El error más famoso de Python

Este merece su propia sección. Léelo despacio:

def registrar(nombre, historial=[]):     # ❌ TRAMPA
    historial.append(nombre)
    return historial

registrar("Ana")      # ['Ana']
registrar("Carlos")   # ['Ana', 'Carlos']   😱 ¿de dónde sale Ana?
El valor por defecto se evalúa una sola vez, cuando Python define la función — no cada vez que la llamas. Esa lista es un único objeto compartido por todas las llamadas.

Puedes comprobarlo tú mismo, porque el objeto está ahí, a la vista:

registrar.__defaults__     # (['Ana', 'Carlos'],)  ← el defecto ha cambiado

La solución es el idioma estándar de Python:

def registrar(nombre, historial=None):   # ✅
    if historial is None:
        historial = []
    historial.append(nombre)
    return historial
Solo pasa con valores por defecto mutables (listas, diccionarios, conjuntos). Con 0, "", None o una tupla no hay problema, porque no se pueden modificar. Es la misma frontera mutable/inmutable de la lección anterior.

4. *args y **kwargs: número variable de argumentos

def inspeccionar(*args, **kwargs):
    return f"args={args} kwargs={kwargs}"

inspeccionar(1, 2, a=3)
# args=(1, 2) kwargs={'a': 3}

*args recoge los posicionales sobrantes en una tupla; **kwargs recoge los que vienen con nombre en un diccionario. Los nombres son pura convención — lo que hace la magia son el * y el **.

Y al revés: desempaquetar al llamar

def coordenadas(x, y, z):
    return (x, y, z)

punto = [1, 2, 3]
coordenadas(*punto)         # (1, 2, 3)  — reparte la lista en los 3 parámetros

datos = {"x": 9, "y": 8, "z": 7}
coordenadas(**datos)        # (9, 8, 7)  — reparte el dict por nombre

5. Forzar que se use el nombre: el * solitario

def dividir(a, b, *, redondear=False):
    resultado = a / b
    return round(resultado) if redondear else resultado

dividir(7, 2, redondear=True)   # 4   ✅
dividir(7, 2, True)             # ❌ TypeError: takes 2 positional arguments but 3 were given

Todo lo que va después del * solo se puede pasar por nombre. Es la técnica que usan las propias built-ins que viste en la lección 031: sorted(datos, key=...) o zip(a, b, strict=True) te obligan a nombrarlos precisamente por esto — para que la llamada siga siendo legible dentro de un año.

6. El scope: dónde vive cada variable

Cuando Python encuentra un nombre, lo busca en cuatro sitios, en este orden — la regla LEGB:

Local → dentro de la función actual

Enclosing → en la función que la contiene

Global → a nivel del módulo

Built-in → las funciones de la lección 031

x = "global"

def externa():
    x = "encerrada"
    def interna():
        return x          # encuentra la de 'externa' antes que la global
    return interna()

externa()      # 'encerrada'

Leer sí, escribir no

Desde dentro de una función puedes leer una variable global, pero en cuanto intentas asignarle algo, Python la considera local:

contador = 0

def incrementar():
    contador += 1     # ❌ UnboundLocalError: cannot access local variable
                      #    'contador' where it is not associated with a value

Las dos salidas, según lo que necesites:

def incrementar():
    global contador       # modifica la del módulo
    contador += 1

def hacer_contador():
    n = 0
    def sumar():
        nonlocal n        # modifica la de la función que la envuelve
        n += 1
        return n
    return sumar

c = hacer_contador()
c(), c(), c()             # 1, 2, 3   — cada llamada recuerda su propio n
Ese último ejemplo es un closure: una función que recuerda el entorno donde nació. Lo trabajaste a fondo en la lección 012. Aquí solo se trata de ver de dónde sale la regla.
Sobre global: funciona, pero casi siempre es señal de mal diseño. Una función que modifica estado de fuera es impredecible y difícil de testear — justo lo contrario de las funciones puras de la lección 011. Antes de escribir global, pregúntate si no deberías devolver el valor.

7. Devolver varias cosas

def minmax(numeros):
    return min(numeros), max(numeros)    # esto es una TUPLA

minimo, maximo = minmax([3, 1, 4])       # unpacking al recibir
type(minmax([3, 1, 4]))                  # <class 'tuple'>

No hay sintaxis especial: Python devuelve una tupla y tú la desempaquetas. Es la misma tupla-como-registro de la lección anterior.

Compruébate antes de seguir

¿Por qué def f(x, lista=[]) arrastra datos entre llamadas?

Porque el valor por defecto se evalúa una única vez, en el momento de definir la función, no en cada llamada. Todas las invocaciones comparten exactamente el mismo objeto lista, así que las modificaciones se acumulan entre llamadas sucesivas.

¿Qué recoge *args, y en qué tipo lo guarda?

Recoge todos los argumentos posicionales sobrantes que no encajaron en los parámetros declarados, y los agrupa en una tupla. Su hermano **kwargs hace lo propio con los pasados por nombre, pero los guarda en un diccionario.

¿Qué significa el * solitario en def f(a, *, b)?

Que todo parámetro escrito después de él solo puede pasarse por nombre, nunca por posición. Sirve para obligar a que las llamadas sean legibles, y es la técnica que usan built-ins como sorted con su parámetro key.

¿Por qué falla asignar a una variable global sin declararla?

Porque en cuanto Python ve una asignación a ese nombre dentro de la función, la trata como variable local en todo el cuerpo. Al intentar leerla antes de darle valor lanza UnboundLocalError. Para modificar la de fuera hace falta global o nonlocal.
