Estabilidad y pares bloqueantes

El concepto que hace que Gale-Shapley valga la pena — el cierre de la Rama A

¿Qué es un matching?

Un matching es una asignación entre dos conjuntos del mismo tamaño donde cada elemento de un conjunto se empareja con exactamente uno del otro. 

Participantes: {A, B, C}
Destinos:      {M, V, Bcn}

Matching posible:
  A → M,  B → V,  C → Bcn

¿Qué significa que sea estable?

Un matching es estable si no hay ningún par bloqueante.

¿Qué es un par bloqueante?

Un par bloqueante son dos elementos (uno de cada conjunto) que no están emparejados entre sí pero preferirían estar juntos antes que con su asignación actual.

Ejemplo concreto

Preferencias de candidatos (de más a menos preferido):

Ana:     M > Bcn > V
Carlos:  Bcn > V > M
Beatriz: V > M > Bcn

Preferencias de destinos:

Madrid:    A > B > C
Barcelona: C > A > B
Valencia:  B > A > C

Matching actual:

Ana → Barcelona
Carlos → Madrid
Beatriz → Valencia

Pregunta: ¿hay algún par bloqueante?

  1. Ana prefiere Madrid antes que Barcelona ✅
  2. Madrid prefiere Ana antes que Carlos (su asignado actual) ✅
Ana y Madrid son un par bloqueante: ninguno está con el otro, y ambos preferirían estar juntos. El matching es inestable.

¿Por qué es importante la estabilidad?

Si el matching es inestable, Ana y Madrid tienen incentivos para saltarse el sistema e intentar un acuerdo bilateral. En un proceso selectivo, eso genera conflictos, reclamaciones y sensación de injusticia.

Gale-Shapley garantiza que siempre se obtiene un matching estable.

Propiedades de los matchings estables

  • Puede haber múltiples matchings estables para el mismo conjunto de preferencias
  • Gale-Shapley produce el óptimo para el lado que propone (candidatos proponen → mejor para candidatos)
  • El lado que recibe propuestas obtiene el peor matching estable posible para ellos
Esto no es un adelanto suelto: en la lección 007 (Rama B) vas a demostrar por qué es así, no solo comprobarlo con un ejemplo.

En código: detectar par bloqueante

def es_par_bloqueante(prefs_candidatos, prefs_destinos,
                      matching, candidato, destino):
    """
    True si el candidato y el destino preferirían estar juntos
    antes que con sus asignaciones actuales.
    """
    destino_actual = matching[candidato]
    candidato_actual = obtener_asignado(destino, matching)

    candidato_quiere = (prefs_candidatos[candidato].index(destino) <
                        prefs_candidatos[candidato].index(destino_actual))
    destino_quiere = (prefs_destinos[destino].index(candidato) <
                      prefs_destinos[destino].index(candidato_actual))

    return candidato_quiere and destino_quiere
