lambda, map, filter y comprehensions

Pista 4, lección 3 — el kit clásico, y por qué Python prefiere otro

Funciones lambda

Una lambda es una función sin nombre, escrita en una sola expresión. Nada más. El nombre viene del cálculo lambda de Church que vimos en la lección 011 — es literalmente la notación de 1936. 

def doblar(x):
    return x * 2

doblar = lambda x: x * 2     # exactamente lo mismo

Sintaxis: lambda parámetros: expresión

El return es implícito. No lleva llaves, ni bloque, ni nombre.

lambda: 42                          # cero parámetros
lambda x: x ** 2                    # uno
lambda x, y: x + y                  # dos
lambda c: (-c["nota"], c["nombre"]) # devolviendo una tupla (desempate)
lambda x, base=10: x * base         # con valor por defecto

Los límites

Una lambda sólo puede contener una expresión. Nada de if en bloque, ni for, ni asignaciones, ni try, ni varias líneas: 

lambda x: if x > 0: return x      # ❌ SyntaxError
lambda x: x if x > 0 else -x     # ✅ el ternario SÍ es una expresión
Regla práctica que ahorra discusiones: si la lambda necesita un nombre, no querías una lambda. doblar = lambda x: x * 2 es peor que def doblar(x): return x * 2 — pierdes el nombre real en los tracebacks (<lambda>), pierdes el docstring, y no ganas nada. La PEP 8 lo dice explícitamente.

Dónde sí

La lambda brilla cuando es un argumento de usar y tirar:

sorted(candidatos, key=lambda c: c["nota"])
sorted(candidatos, key=lambda c: (-c["nota"], c["nombre"]))   # desempate
max(plazas, key=lambda p: p["vacantes"])

map(): transformar

map(funcion, iterable) aplica la función a cada elemento. Es la versión funcional del bucle que transforma: 

# Imperativo
mayusculas = []
for n in nombres:
    mayusculas.append(n.upper())

# Funcional
mayusculas = list(map(str.upper, nombres))
map devuelve un iterador perezoso, no una lista. Si haces print(map(...)) verás <map object at 0x...>. Para ver el contenido hay que consumirlo con list(), un for, o pasárselo a otra función. Esa pereza es el tema de la lección 014 — y es una virtud, no un estorbo.

Con varios iterables

notas_teoria  = [7, 8, 5]
notas_practica = [9, 6, 8]

medias = list(map(lambda t, p: (t + p) / 2, notas_teoria, notas_practica))
# [8.0, 7.0, 6.5]

Se para en cuanto el más corto se agota.

filter(): seleccionar

filter(predicado, iterable) se queda con los elementos para los que el predicado da verdadero. Un predicado es simplemente una función que devuelve un booleano. 

# Imperativo
aprobados = []
for n in notas:
    if n >= 5:
        aprobados.append(n)

# Funcional
aprobados = list(filter(lambda n: n >= 5, notas))

# Truco: filter(None, ...) quita todo lo "falsy"
sucios = ["Ana", "", None, "Carlos", 0, "Beatriz"]
list(filter(None, sucios))     # ['Ana', 'Carlos', 'Beatriz']

Encadenando

resultado = list(
    map(lambda c: c["nombre"],
        filter(lambda c: c["nota"] >= 5, candidatos))
)

Funciona. Y ahí está el problema: para saber qué hace hay que leerlo de dentro hacia fuera, y el filter — que ocurre primero — está escrito el último.

Comprehensions: la respuesta de Python

Guido van Rossum llegó a proponer eliminar map, filter y reduce de Python 3. No lo consiguió del todo (reduce fue desterrado a functools), pero el mensaje quedó claro: en Python, la forma idiomática de hacer esto son las comprehensions.

[expresión for elemento in iterable if condición]

La expresión es el map. La condición es el filter. Y se leen en el orden en que ocurren.

Con map/filterCon comprehension
list(map(str.upper, ns)) [n.upper() for n in ns]
list(filter(lambda n: n>=5, ns)) [n for n in ns if n >= 5]
list(map(f, filter(g, ns))) [f(n) for n in ns if g(n)]

El ejemplo encadenado de antes, reescrito:

resultado = [c["nombre"] for c in candidatos if c["nota"] >= 5]
Misma semántica funcional — sin mutación, sin acumulador, sin bucle explícito — pero legible de izquierda a derecha. Las comprehensions son programación funcional; simplemente con la sintaxis que Python eligió.

Las cuatro familias

# Lista
[c["nota"] for c in candidatos]

# Diccionario — clave: valor
{c["nombre"]: c["nota"] for c in candidatos}

# Conjunto — deduplicación gratis
{c["cuerpo"] for c in candidatos}

# Generador — ojo, paréntesis: NO construye nada en memoria (lección 014)
(c["nota"] for c in candidatos)

Un caso que usarás mucho, invertir un diccionario: 

ranking = {"Sevilla": 1, "Cádiz": 2, "Huelva": 3}
por_puesto = {puesto: ciudad for ciudad, puesto in ranking.items()}
# {1: 'Sevilla', 2: 'Cádiz', 3: 'Huelva'}

Anidadas — con cuidado

# Aplanar una matriz (matematicas/matrice.py)
matriz = [[1, 2], [3, 4], [5, 6]]
plana = [x for fila in matriz for x in fila]      # [1, 2, 3, 4, 5, 6]
El orden de los for es el mismo que tendrían anidados en un bucle normal: el de fuera primero. Se lee «para cada fila de la matriz, para cada x de la fila». Con dos niveles vale; con tres, escribe un bucle.

Producto cartesiano y condicional en la expresión

# Todos los emparejamientos posibles (¡la fuerza bruta de la lección 005!)
pares = [(c, p) for c in candidatos for p in plazas]

# if/else va ANTES del for, porque forma parte de la expresión
etiquetas = ["apto" if n >= 5 else "no apto" for n in notas]

# el if solo (filtro) va DESPUÉS del for
aprobadas = [n for n in notas if n >= 5]
Esta asimetría confunde a todo el mundo al principio. La razón es simple: x if c else y es una expresión y ocupa el hueco del map; el if suelto del final es un filtro y ocupa el hueco del filter. Son cosas distintas en sitios distintos.

Entonces, ¿cuándo usar map/filter?

SituaciónElige
Caso general en Python Comprehension
La función ya existe con nombre: map(str.strip, xs) map — es más corto y no inventa una variable
Estás componiendo funciones (lección 012) y necesitas map como valor map/filter
La lógica no cabe en una expresión Un bucle normal, sin complejos
Necesitas break, o llevar estado entre iteraciones Un bucle normal. Siempre.
El antipatrón a evitar: la comprehension de cinco líneas con tres for, dos if y un ternario dentro. Cabe en una línea, sí, pero nadie — incluido tú dentro de dos meses — puede leerla. La brevedad no es el objetivo; la claridad sí.
