Funciones de primera clase y composición

Pista 4, lección 2 — cuando la función es un dato más

La idea de "primera clase"

Se dice que en un lenguaje las funciones son ciudadanos de primera clase cuando puedes hacer con ellas exactamente lo mismo que con un número o un string:

Guardarlas en una variable · meterlas en una lista o un diccionario · pasarlas como argumento · devolverlas desde otra función · crearlas sobre la marcha.

En Python lo son, y de la forma más literal posible: def no es una declaración mágica, es una asignación. Escribir def doblar(x): return x * 2 crea un objeto función y lo enlaza al nombre doblar, igual que doblar = 2 enlazaría un entero. 

def doblar(x):
    return x * 2

print(type(doblar))     # <class 'function'>
print(doblar.__name__)  # 'doblar'   ← tiene atributos, es un objeto

otro_nombre = doblar    # SIN paréntesis: copio la función, no la llamo
print(otro_nombre(21))  # 42
El detalle que lo cambia todo: doblar es la función. doblar() es el resultado de llamarla. Confundir los dos es el error número uno de esta lección. Si algo "no funciona" en el resto de la pista, empieza siempre por preguntarte si te sobran o te faltan paréntesis.

Funciones en estructuras de datos

Como son objetos, caben en un diccionario. Y un diccionario de funciones es la alternativa funcional a una cadena de if/elif: 

def por_nota(c):      return -c["nota"]
def por_nombre(c):    return c["nombre"]
def por_antiguedad(c): return -c["antiguedad"]

CRITERIOS = {
    "nota":       por_nota,
    "nombre":     por_nombre,
    "antiguedad": por_antiguedad,
}

def listar(candidatos, criterio):
    return sorted(candidatos, key=CRITERIOS[criterio])

Añadir un criterio nuevo es añadir una línea al diccionario, no tocar un if de veinte ramas. En OOP resolverías esto con el patrón Strategy: una interfaz, tres clases, una factoría. Aquí es un dict.

Funciones de orden superior

Una función es de orden superior si hace alguna de estas dos cosas (o las dos): recibe una función como argumento, o devuelve una función.

Recibir una función

Ya has usado varias sin saber que lo eran:

sorted(candidatos, key=por_nota)   # ← key es una función (lección 002)
max(candidatos, key=por_nota)
min(candidatos, key=por_nota)

Y puedes escribir las tuyas. Fíjate en cómo el parámetro condicion convierte una función rígida en una plantilla:

def aplicar_dos_veces(f, x):
    return f(f(x))

print(aplicar_dos_veces(doblar, 5))   # 20


def contar_si(elementos, condicion):
    """Cuenta cuántos elementos cumplen la condición."""
    return sum(1 for e in elementos if condicion(e))

aprobados = contar_si(notas, lambda n: n >= 5)
suspensos = contar_si(notas, lambda n: n < 5)
sobresalientes = contar_si(notas, lambda n: n >= 9)
El patrón de fondo: parametriza el comportamiento, no sólo los datos. Antes pasabas números; ahora pasas trozos de lógica.

Devolver una función: closures

Aquí es donde la mayoría de la gente se atasca, así que vamos despacio. 

def multiplicador(factor):
    def multiplicar(x):
        return x * factor      # ← usa 'factor', que viene de la función de fuera
    return multiplicar          # ← devuelve la función SIN llamarla

doble = multiplicador(2)
triple = multiplicador(3)

print(doble(10))    # 20
print(triple(10))   # 30

multiplicador(2) no multiplica nada: fabrica una función que multiplica por 2. Y esa función recuerda el valor 2 aunque multiplicador ya haya terminado de ejecutarse y su marco de pila haya desaparecido.

Closure (o clausura): una función que "captura" y conserva las variables del ámbito donde fue definida. Python guarda esas variables vivas mientras la función interna exista. 

print(doble.__closure__[0].cell_contents)   # 2  ← ahí está, guardado
Un closure es un objeto pobre, y un objeto es un closure rico. Compara:

En un lenguaje OOP escribirías class Multiplicador { private $factor; __construct($f) {...} public function __invoke($x) { return $x * $this->factor; } }. Estado guardado en el constructor, comportamiento en un método.

El closure hace lo mismo: factor es el estado, multiplicar es el método. Si tu clase tiene un solo método además del __init__, probablemente quería ser un closure.

El gotcha del closure en un bucle

Este te va a morder alguna vez, así que mejor ahora:

funciones = []
for i in range(3):
    funciones.append(lambda x: x + i)

print([f(10) for f in funciones])   # [12, 12, 12]  😱 esperabas [10, 11, 12]

El closure captura la variable i, no su valor en ese instante. Cuando por fin llamas a las funciones, el bucle ya terminó e i vale 2 para todas. La solución idiomática es forzar la captura con un argumento por defecto (que sí se evalúa en el momento de la definición — es el mismo mecanismo del gotcha de la lección 011, esta vez a tu favor): 

funciones = [lambda x, i=i: x + i for i in range(3)]
print([f(10) for f in funciones])   # [10, 11, 12] ✅

Composición de funciones

Componer es la operación básica del paradigma: si f transforma A en B y g transforma B en C, entonces existe una función que transforma A en C. En matemáticas se escribe g ∘ f. 

def limpiar(s):     return s.strip()
def minusculas(s):  return s.lower()
def sin_tildes(s):
    tabla = str.maketrans("áéíóúü", "aeiouu")
    return s.translate(tabla)

Anidando a mano, se lee al revés — de dentro hacia fuera:

resultado = sin_tildes(minusculas(limpiar("  Sevilla Este  ")))

Con tres funciones aguanta. Con seis es ilegible. Construye la herramienta:

from functools import reduce

def componer(*funciones):
    """Devuelve una función que las aplica de izquierda a derecha."""
    def compuesta(valor):
        return reduce(lambda acc, f: f(acc), funciones, valor)
    return compuesta

normalizar = componer(limpiar, minusculas, sin_tildes)

print(normalizar("  Sevilla Este  "))   # 'sevilla este'
Lee la diferencia en voz alta. sin_tildes(minusculas(limpiar(x))) se lee «sin tildes de minúsculas de limpiar de x». componer(limpiar, minusculas, sin_tildes) se lee «limpiar, luego minúsculas, luego sin tildes». La segunda es el orden en que ocurren las cosas.

Y fíjate en lo que has creado: normalizar es una función nueva, con nombre propio, reutilizable, testeable — que no existía en tu código y no ha requerido escribir un def. Ese es el músculo que esta pista entrena.

Pipeline: componer sobre colecciones

def normalizar_todos(nombres):
    return [normalizar(n) for n in nombres]

# o encadenando pasos completos:
procesar = componer(
    lambda ns: [n for n in ns if n.strip()],   # quitar vacíos
    lambda ns: [normalizar(n) for n in ns],    # normalizar
    sorted,                                    # ordenar
)

sorted entra directamente en la composición porque es una función como cualquier otra. Esa uniformidad — todo es una función de una entrada a una salida — es lo que hace que las piezas encajen.

Cuándo NO componer

La composición se rompe en cuanto una función necesita dos entradas, o devuelve dos salidas, o puede fallar. Un componer() casero sólo encadena funciones de un argumento.
