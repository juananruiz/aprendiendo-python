Decoradores de propósito general

Pista 4, lección 7 — funciones que envuelven funciones

Los decoradores son la cara visible de la programación funcional en el Python cotidiano: los ves en Flask, en pytest, en FastAPI, en SQLAlchemy. Y, aunque parecen magia, no hay nada nuevo en ellos. Son closures (lección 012) de orden superior, servidos con azúcar sintáctico.

El azúcar

@decorador encima de un def significa exactamente esto:

mi_funcion = decorador(mi_funcion) 

# Estas dos formas son idénticas:

@cronometrar
def calcular():
    ...

# ---

def calcular():
    ...
calcular = cronometrar(calcular)

Eso es todo. La @ ahorra escribir el nombre tres veces y pone la intención arriba, donde se ve. No hay nada más.

Construyendo uno, paso a paso

Objetivo: un decorador que mida cuánto tarda una función.

Paso 1 — una función que recibe una función

def cronometrar(funcion):
    ...
    return algo

Tiene que devolver algo llamable, porque quien use calcular() espera poder llamarlo igual que antes.

Paso 2 — el envoltorio

def cronometrar(funcion):
    def envoltorio():
        return funcion()
    return envoltorio

Ya funciona… para funciones sin argumentos. Insuficiente.

Paso 3 — aceptar cualquier firma

def cronometrar(funcion):
    def envoltorio(*args, **kwargs):
        return funcion(*args, **kwargs)
    return envoltorio
*args, **kwargs es lo que hace que un decorador sea de propósito general: recoge cualquier combinación de argumentos posicionales y nombrados, y los reenvía intactos. Sin esto, tu decorador sólo sirve para una firma concreta.

Paso 4 — hacer algo antes y después

import time

def cronometrar(funcion):
    def envoltorio(*args, **kwargs):
        inicio = time.perf_counter()
        resultado = funcion(*args, **kwargs)      # ← no olvides el resultado
        transcurrido = time.perf_counter() - inicio
        print(f"{funcion.__name__} tardó {transcurrido:.4f}s")
        return resultado                          # ← ni devolverlo
    return envoltorio
Los dos olvidos clásicos: no capturar el resultado de la función envuelta, o no devolverlo. En ambos casos tu función decorada empieza a devolver None silenciosamente. Si un decorador "rompe" algo, mira primero el return.

Paso 5 — @wraps, siempre

from functools import wraps

def cronometrar(funcion):
    @wraps(funcion)
    def envoltorio(*args, **kwargs):
        inicio = time.perf_counter()
        resultado = funcion(*args, **kwargs)
        print(f"{funcion.__name__} tardó {time.perf_counter() - inicio:.4f}s")
        return resultado
    return envoltorio

Sin @wraps perderías el nombre y el docstring de la función original (lección 015). Este es el decorador terminado.

Decoradores con parámetros

Ahora quieres @reintentar(veces=3). Fíjate en el detalle: hay paréntesis, o sea que reintentar(veces=3) se ejecuta primero y su resultado es el decorador. Necesitas un nivel más de anidamiento:

@decorador → 2 niveles: decorador → envoltorio
@decorador(args) → 3 niveles: fábrica → decorador → envoltorio 

from functools import wraps
import time

def reintentar(veces=3, espera=1.0):
    def decorador(funcion):                       # nivel 2
        @wraps(funcion)
        def envoltorio(*args, **kwargs):          # nivel 3
            for intento in range(1, veces + 1):
                try:
                    return funcion(*args, **kwargs)
                except Exception as e:
                    if intento == veces:
                        raise
                    print(f"Intento {intento} falló ({e}). Reintentando…")
                    time.sleep(espera)
        return envoltorio
    return decorador


@reintentar(veces=5, espera=0.5)
def consultar_api(url):
    ...

Léelo de fuera hacia dentro:

reintentar(veces=5, espera=0.5) → devuelve `decorador` decorador(consultar_api) → devuelve `envoltorio` consultar_api = envoltorio
Si quieres que funcione con y sin paréntesis (@reintentar y @reintentar(veces=5)), hay que detectar si el primer argumento es llamable. Es un truco conocido, pero añade ruido: en la práctica, elige una de las dos formas y sé consistente.

Un catálogo útil

Registro (el patrón de Flask)

RUTAS = {}

def ruta(camino):
    def decorador(funcion):
        RUTAS[camino] = funcion      # sólo registra; NO envuelve
        return funcion               # devuelve la original intacta
    return decorador

@ruta("/candidatos")
def listar_candidatos(): ...

Aquí el decorador no modifica nada: usa el momento de la definición como gancho para apuntarse en un diccionario. Es el diccionario de funciones de la lección 012, poblado declarativamente. Así funcionan @app.route de Flask y @app.get de FastAPI.

Validación de argumentos

def validar_positivo(funcion):
    @wraps(funcion)
    def envoltorio(*args, **kwargs):
        if any(isinstance(a, (int, float)) and a < 0 for a in args):
            raise ValueError(f"{funcion.__name__} no acepta negativos")
        return funcion(*args, **kwargs)
    return envoltorio

Registro de llamadas (logging)

def trazar(funcion):
    @wraps(funcion)
    def envoltorio(*args, **kwargs):
        firma = ", ".join([*map(repr, args),
                           *(f"{k}={v!r}" for k, v in kwargs.items())])
        print(f"→ {funcion.__name__}({firma})")
        resultado = funcion(*args, **kwargs)
        print(f"← {resultado!r}")
        return resultado
    return envoltorio

Apilar decoradores

@cronometrar
@trazar
@validar_positivo
def calcular_baremo(experiencia, formacion):
    ...

Se aplican de abajo arriba: cronometrar(trazar(validar_positivo(calcular_baremo))). Y se ejecutan de arriba abajo: el cronómetro es el más externo, así que mide también el tiempo de los otros dos.

El orden importa. @cronometrar encima de @lru_cache mide los aciertos de caché (casi 0 s). @lru_cache encima de @cronometrar cachea el resultado del cronometrado, y sólo verás la medición la primera vez. Cuando un decorador apilado se comporte raro, dibuja el orden de envoltura.

Dónde encaja esto en el paradigma

Un decorador es composición de funciones (lección 012) con otra cara: decorador ∘ funcion. Y sirve para lo que los funcionales llaman preocupaciones transversales — cronometrar, cachear, registrar, reintentar, autorizar — que en OOP resolverías con herencia, mixins o programación orientada a aspectos.

En OOP (PHP, Java...)Aquí
Clase base con lógica comúnDecorador aplicado a cada función
Middleware de frameworkDecorador
Patrón Decorator (GoF) con interfacesDecorador de una línea
Anotaciones + reflexiónDecorador de registro
Cuándo NO decorar. Un decorador esconde código en la distancia: leyendo calcular_baremo() no ves que hay tres capas encima. Úsalos para lo transversal y genérico, nunca para lógica de negocio. Si un decorador sólo se aplica a una función, probablemente querías escribir esas líneas dentro de la función.
