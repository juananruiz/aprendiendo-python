Hash tables: el dict por dentro

Por qué buscar en un diccionario cuesta lo mismo con diez elementos que con diez millones

En la lección 032 mediste algo que parecía magia: buscar en un set de 100.000 elementos tardaba lo mismo que en uno de 1.000 — 22.493 veces más rápido que la lista. Esta lección explica cómo está hecho ese truco. Y no es magia: es una idea muy elegante con un precio muy concreto.

1. El problema que resuelve

Para encontrar algo en una lista hay que mirar elemento por elemento: O(n). La pregunta de la que nace la tabla hash es descarada:

¿Y si en vez de buscar dónde está algo, pudiéramos calcular dónde tiene que estar?

2. La función hash

Una función hash convierte cualquier objeto en un número. Python la tiene incorporada: 

hash(42)              # 42
hash("Ana")           # un entero enorme, p.ej. -2155106213085494282
hash(("Sevilla", 3))  # también funciona: las tuplas son hashables
hash(["Ana"])         # TypeError: unhashable type: 'list'

Con ese número se calcula la posición con un simple resto:

indice = hash(clave) % numero_de_cubos

Y ya está. Sabiendo la clave, sabes la posición sin buscar. Eso es O(1).

Un detalle que sorprende: hash("Ana") da un número distinto en cada ejecución de Python. Compruébalo: python3 -c "print(hash('Ana'))" dos veces. Es intencionado — se llama hash randomization y protege frente a ataques que provocan colisiones a propósito (Python usa el algoritmo siphash13). Los enteros, en cambio, siempre se hashean a sí mismos: hash(42) es 42 siempre. Por eso nunca guardes un hash en disco esperando encontrarlo igual mañana.

3. Las colisiones

Dos claves distintas pueden dar el mismo índice. Es inevitable: hay infinitas claves posibles y un número finito de cubos. A eso se le llama colisión, y hay que resolverlo.

La técnica más simple es el encadenamiento: cada cubo guarda una pequeña lista, y si hay colisión se añade a esa lista. Aquí está una tabla hash completa en veinte líneas: 

class TablaHash:
    def __init__(self, n_cubos=8):
        self.n = n_cubos
        self.cubos = [[] for _ in range(n_cubos)]

    def _indice(self, clave):
        return hash(clave) % self.n           # ← aquí está toda la magia

    def poner(self, clave, valor):
        cubo = self.cubos[self._indice(clave)]
        for i, (k, v) in enumerate(cubo):
            if k == clave:
                cubo[i] = (clave, valor)      # actualizar si ya existía
                return
        cubo.append((clave, valor))

    def obtener(self, clave):
        for k, v in self.cubos[self._indice(clave)]:
            if k == clave:
                return v
        raise KeyError(clave)

Metiendo cinco nombres en ocho cubos, esta es la distribución real que se obtiene: 

[0, 1, 0, 1, 1, 0, 2, 0]     ← cinco elementos repartidos; un cubo tiene dos

El peor caso: cuando todo colisiona

Si todas las claves caen en el mismo cubo, la tabla hash se convierte en... una lista. Y buscar vuelve a ser O(n): 

t = TablaHash(n_cubos=1)      # un único cubo: todo colisiona
# distribución: [3]  ← los tres elementos en el mismo sitio

Por eso el set de la lección 032 ocupaba 5 veces más memoria que la lista: para que las colisiones sean raras, la tabla necesita cubos de sobra. Python mantiene la ocupación por debajo de dos tercios y, cuando se pasa, crea una tabla más grande y recoloca todo (rehashing). Ese es el precio del O(1).

4. Por qué las claves deben ser inmutables

Ya sabías que una lista no puede ser clave de un diccionario. Ahora ya sabes por qué:

La posición de una clave se calcula a partir de su contenido. Si el contenido cambiara después de guardarla, su hash cambiaría, y el valor quedaría archivado en un cubo donde nadie lo va a buscar jamás.

De ahí la regla del lenguaje: solo lo hashable —lo inmutable— puede ser clave. Números, strings, tuplas y frozenset sí; listas, diccionarios y conjuntos, no.

5. Los tres usos que te vas a encontrar

# 1. Índice de búsqueda: de O(n) a O(1)
por_nombre = {c["nombre"]: c for c in candidatos}
por_nombre["Ana"]                      # instantáneo

# 2. Eliminar duplicados / pertenencia
vistos = set()
if elemento not in vistos:             # O(1)
    vistos.add(elemento)

# 3. Contar y agrupar
from collections import Counter, defaultdict
Counter(palabras).most_common(3)

El caso 2 es el que vas a usar en la siguiente lección: el conjunto de nodos ya visitados en una búsqueda en anchura es una tabla hash, y de ahí sale buena parte de su eficiencia.

Compruébate antes de seguir

¿Cómo consigue una tabla hash localizar algo sin recorrer nada?

Porque calcula la posición directamente a partir de la clave: aplica una función hash y toma el resto entre el número de cubos. En lugar de buscar dónde está el dato, deduce dónde tiene que estar, y salta ahí de una vez.

¿Qué es una colisión y cuándo degrada el rendimiento a O(n)?

Ocurre cuando dos claves distintas producen el mismo índice de cubo. Si son raras, apenas cuestan; pero si casi todas las claves caen en el mismo sitio, cada cubo se convierte en una lista larga y buscar vuelve a exigir recorrerla entera.

¿Por qué hash("Ana") cambia entre ejecuciones?

Porque Python aleatoriza la semilla del hash de cadenas al arrancar, como defensa frente a ataques que provocarían colisiones masivas deliberadas. Es la razón de que jamás debas almacenar un hash de texto esperando reproducirlo en otra sesión.
