Grafos y búsqueda en anchura

El algoritmo que hay detrás de «personas que quizá conozcas» y del GPS

Esta lección junta tres cosas que ya sabes por separado: los diccionarios y conjuntos para representar el grafo, la deque como cola de pendientes, y el bucle while que las procesa. El resultado es uno de los algoritmos más útiles que existen.

1. Qué es un grafo

Un grafo es simplemente un conjunto de nodos conectados por aristas. Nada más. Con esa idea tan simple se modelan redes sociales, mapas de carreteras, dependencias entre tareas, rutas de vuelo o el propio enlazado de esta web.

En Python se representa de la forma más natural posible: un diccionario donde cada clave es un nodo y su valor es la lista de vecinos. Se llama lista de adyacencia: 

grafo = {
    "Ana":   ["Bruno", "Clara"],
    "Bruno": ["Diego"],
    "Clara": ["Diego", "Elena"],
    "Diego": ["Fran"],
    "Elena": ["Fran"],
    "Fran":  [],
}
Este grafo es dirigido: que Ana conozca a Bruno no implica que Bruno conozca a Ana. Para uno no dirigido (una amistad mutua, una carretera de doble sentido) basta con añadir la arista en ambas direcciones.

2. La idea de la búsqueda en anchura

BFS (Breadth-First Search) responde a dos preguntas:

1. ¿Hay camino de A a B?

2. ¿Cuál es el camino más corto de A a B?

Y lo hace explorando por capas: primero todos los vecinos directos, luego los vecinos de esos, luego los siguientes. Como la onda que se expande al tirar una piedra al agua. Por eso el primer camino que encuentra hasta el destino es, necesariamente, el más corto en número de saltos.

La pieza clave: la cola

Lo que hace que la exploración sea «por capas» es usar una cola FIFO: el primero que entra es el primero que sale. Si usaras una pila (LIFO), el algoritmo se lanzaría en profundidad por una rama antes de mirar las demás — eso sería DFS, otro algoritmo distinto. 

from collections import deque      # la de la lección 003

cola = deque(["Ana"])
cola.append("Bruno")     # entra por la derecha
cola.popleft()           # sale por la izquierda: "Ana"  → O(1)

3. El algoritmo

from collections import deque

def distancias_desde(grafo, inicio):
    """Devuelve {nodo: nº de saltos desde inicio} para todo lo alcanzable."""
    distancias = {inicio: 0}
    cola = deque([inicio])

    while cola:
        nodo = cola.popleft()
        for vecino in grafo.get(nodo, []):
            if vecino not in distancias:      # ← el dict hace de "visitados"
                distancias[vecino] = distancias[nodo] + 1
                cola.append(vecino)

    return distancias

Sobre el grafo de arriba, partiendo de Ana:

{'Ana': 0, 'Bruno': 1, 'Clara': 1, 'Diego': 2, 'Elena': 2, 'Fran': 3}

Se lee solo: Bruno y Clara están a un salto (capa 1), Diego y Elena a dos, Fran a tres.

Recuperar el camino, no solo la distancia

def camino_mas_corto(grafo, inicio, destino):
    if inicio == destino:
        return [inicio]
    cola = deque([[inicio]])          # la cola guarda CAMINOS, no nodos
    visitados = {inicio}

    while cola:
        camino = cola.popleft()
        for vecino in grafo.get(camino[-1], []):
            if vecino == destino:
                return camino + [vecino]
            if vecino not in visitados:
                visitados.add(vecino)
                cola.append(camino + [vecino])

    return None                       # no hay camino

camino_mas_corto(grafo, "Ana", "Fran")   # ['Ana', 'Bruno', 'Diego', 'Fran']
camino_mas_corto(grafo, "Fran", "Ana")   # None  — el grafo es dirigido

4. El detalle que rompe el algoritmo si lo olvidas

El conjunto visitados no es una optimización: es lo que impide que el algoritmo entre en un bucle infinito. Si el grafo tiene un ciclo (A→B→A, tan común en una red social), sin él estarías dando vueltas para siempre.

Y fíjate en por qué es un set y no una lista: la comprobación vecino not in visitados se ejecuta una vez por cada arista del grafo. Con un set es O(1); con una lista sería O(n), y el algoritmo entero pasaría de O(V+A) a O(V·A). Es exactamente el «coste escondido» de la lección 021.

Complejidad

ConceptoCostePor qué
TiempoO(V + A)cada nodo entra en la cola una vez; cada arista se mira una vez
MemoriaO(V)la cola y el conjunto de visitados

V = número de vértices (nodos), A = número de aristas.

5. Dónde se usa esto de verdad

  • Redes sociales: «personas que quizá conozcas» son los nodos a distancia 2
  • Grados de separación: el número de Erdős, los seis grados de Kevin Bacon
  • Rutas: el camino con menos transbordos en el metro
  • Juegos: el número mínimo de movimientos para resolver un puzle
  • Rastreadores web: explorar enlaces por niveles de profundidad
El límite de BFS: cuenta saltos, no distancias. Encuentra la ruta con menos transbordos, pero no la más rápida si cada tramo tiene una duración distinta. Para eso hace falta que las aristas tengan peso — y ese es el algoritmo de Dijkstra, la continuación natural de esta lección.

Compruébate antes de seguir

¿Por qué BFS encuentra siempre el camino más corto en saltos?

Porque explora el grafo por capas completas: agota todos los nodos a un salto antes de pasar a los de dos. Cuando alcanza el destino por primera vez, ninguna ruta más corta puede quedar sin explorar, así que la encontrada es mínima.

¿Qué pasaría si quitaras el conjunto de visitados?

En cuanto el grafo tuviera un ciclo, el algoritmo volvería a encolar nodos ya explorados una y otra vez, sin terminar nunca. No es una mejora de rendimiento sino la condición que garantiza que la búsqueda termine.

¿Por qué una cola FIFO y no una pila?

Porque la cola obliga a procesar los nodos en el orden en que fueron descubiertos, completando cada capa antes de avanzar. Con una pila se exploraría primero una rama entera hasta el fondo, que es justamente el comportamiento de la búsqueda en profundidad.
